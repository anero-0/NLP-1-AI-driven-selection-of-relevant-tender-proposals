# Отчёт по проекту: ИИ-отбор релевантных тендерных предложений

## 1. Введение
Данный проект решает задачу ранжирования входящих тендерных предложений (выгрузок из сервиса «Контур.Закупки») с целью выявления наиболее релевантных для компании ООО «Гарпикс». Использование ИИ-ассистента позволяет автоматизировать рутинный труд отдела продаж, сокращая время на анализ сотен строк каждую неделю.

## 2. Исследовательский анализ данных (EDA)
В рамках анализа (см. `EDA_tender.ipynb`) были изучены исторические выгрузки и размеченные данные:
- Выявлены наиболее информативные поля: *Название*, *Способ отбора*, *НМЦ (Начальная максимальная цена)*, *Регион* и *Тип торгов*.
- Проанализировано распределение целевой переменной (попадание в реестр / интерес).
- Обработаны пропуски в числовых полях (например, отсутствие НМЦ или дат).
- Вскрыта проблема скрытых гиперссылок в Excel-выгрузках Контура, что потребовало разработки кастомного парсера на `openpyxl`.

## 3. Проектирование вектора признаков (Feature Engineering)
В скрипте `features.py` реализован конвейер (pipeline) преобразования сырых табличных данных в признаки для ML-моделей:
1. **NLP признак (текст):** Извлечение ключевых слов из поля «Название» (TF-IDF векторизация после базовой очистки и приведения к нижнему регистру).
2. **Категориальные переменные:** Обработка столбцов «Способ отбора», «Регион», «Тип торгов» (применяется One-Hot Encoding внутри ColumnTransformer).
3. **Временные признаки:** Из дат извлекается срочность — вычисляется разница в днях между датой публикации и окончанием приема заявок (`days_to_deadline`).
4. **Числовые признаки:** Значение НМЦ очищается от лишних символов и переводится во `float`, добавляется бинарный флаг `has_price`.

## 4. Обучение моделей и метрики
Сравнение моделей показало, что задача бинарной классификации (где класс 1 = "Тендер интересен", класс 0 = "Мусор") имеет сильный дисбаланс.
Было протестировано несколько алгоритмов с учётом временной последовательности (train_test_split без перемешивания, чтобы имитировать поток новых закупок):
- **Logistic Regression** (baseline) — см. `baseline_model_LogReg.ipynb`. Показала хорошую интерпретируемость, но уступает более сложным моделям на нелинейных зависимостях.
- **Random Forest Classifier** — см. `export_pipeline.ipynb` и `random_forest_comparison.ipynb`. Модель отлично уловила сложные комбинации ключевых слов и ценовых диапазонов.

**Финальные метрики выбранной модели (Random Forest):**
- **Recall (Полнота)**: `0.92` (≥ 0.85 — бизнес-цель выполнена). ИИ практически не пропускает интересные тендеры.
- **Precision (Точность)**: `0.41`.
- **ROC-AUC**: `0.908`.
- Подобран оптимальный порог классификации (`0.106`), при котором соблюдается баланс полноты и точности.

## 5. Инструкция по установке и запуску (Веб-приложение)
Приложение написано на FastAPI.

### Требования:
- Python 3.10+

### Установка:
```bash
git clone https://github.com/anero-0/NLP-1-AI-driven-selection-of-relevant-tender-proposals.git
cd NLP-1-AI-driven-selection-of-relevant-tender-proposals
pip install -r requirements.txt
```

### Запуск:
```bash
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```
После запуска перейдите по адресу `http://localhost:8000`. 
Выгрузки из «Контур.Закупки» формата `.xlsx` можно загружать методом Drag-and-Drop. На выходе получается отсортированная таблица с цветовой индикацией балла, которую можно скачать обратно в `.xlsx`.

## 6. Рекомендации по улучшению системы
1. **Интеграция XGBoost/CatBoost:** В будущих итерациях рекомендуется внедрить градиентный бустинг, который часто показывает превосходство над Случайным лесом (Random Forest) на табличных данных с категориальными переменными.
2. **Анализ заказчиков:** Добавить парсинг ИНН заказчика и проверять его историю (как часто объявляет тендеры, были ли победы ранее), чтобы добавить признак лояльности.
3. **Продвинутый NLP (BERT/LLM):** Заменить TF-IDF на предобученные трансформеры (например, RuBERT) для более глубокого семантического анализа документации (ТЗ), если она будет парситься со страниц площадок.
4. **Контейнеризация:** Упаковать приложение в Docker (с созданием `Dockerfile` и `docker-compose.yml`) для упрощения деплоя на сервер.
